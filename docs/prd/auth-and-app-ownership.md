# PRD：认证与应用归属

## 1. 背景与目标

当前系统允许游客直接创建应用，应用数据存储在 localStorage，不会关联到用户账号。登录后用户无法看到游客期间创建的应用，导致数据丢失风险。本次需求旨在：(1) 强制登录后才能创建应用，确保应用归属明确；(2) 建立用户级别的应用管理；(3) 修复当前创建流程中的中断点，确保用户完成登录后能顺利完成应用创建。

---

## 2. 用户故事

### US-001：登录守卫
**作为** 想要创建应用的用户，**我想要** 在未登录时被引导到登录页，**以便** 确保我创建的应用能保存到账号中。

**验收标准：**
- [ ] 未登录用户访问首页时，输入框区域显示"登录后开始创建"提示，输入框禁用
- [ ] 点击输入框或模板按钮，弹出登录引导（跳转到 /login 或显示登录弹窗）
- [ ] 登录成功后自动返回首页，输入框可用

### US-002：项目列表认证守卫
**作为** 已登录用户，**我想要** 在项目列表页只看到我自己的项目，**以便** 管理我的应用。

**验收标准：**
- [ ] 未登录用户访问 /projects 时，跳转到 /login，携带 redirect 参数
- [ ] 登录后自动跳回 /projects
- [ ] 项目列表仅显示当前登录用户的项目（服务端 userId 隔离已实现，前端需守卫）

### US-003：应用归属账号
**作为** 已登录用户，**我想要** 我创建的每个应用都关联到我的账号，**以便** 在任何设备登录后都能看到我的应用。

**验收标准：**
- [ ] 创建应用时，服务端记录 userId（当前已实现，需确保前端在登录态下调用 API）
- [ ] API 可用时，应用数据同步到服务端，携带用户会话
- [ ] API 不可用时，应用临时存储在 localStorage，下次登录后自动同步（P2 延后）

### US-004：移除游客模式入口
**作为** 产品运营者，**我想要** 移除登录/注册页的"游客模式进入"选项，**以便** 引导所有用户完成注册登录。

**验收标准：**
- [ ] AuthPage 移除"游客模式进入"按钮和相关文案
- [ ] 移除 HomeAuthControls 中的游客相关逻辑（当前无，需确认）

### US-005：登录状态持久化与恢复
**作为** 已登录用户，**我想要** 关闭浏览器后重新打开时自动恢复登录状态，**以便** 无需重复登录。

**验收标准：**
- [ ] 应用启动时调用 checkAuth 恢复会话（当前已实现）
- [ ] 会话过期时（401），自动跳转到登录页并提示"会话已过期，请重新登录"
- [ ] 会话恢复期间显示加载状态（当前已实现）

### US-006：登出后清理本地项目缓存
**作为** 已登录用户，**我想要** 登出后清除本地项目缓存，**以便** 换账号登录时不会看到上一个账号的项目。

**验收标准：**
- [ ] 登出时清除 localStorage 中的项目数据（summaries 和 currentProject）
- [ ] 登出后跳转到首页，显示登录引导

## 4. 验收标准

### US-001：登录守卫
1. 未登录用户访问首页，输入框显示禁用状态（灰色背景、禁用光标），placeholder 显示"登录后开始创建应用"
2. 点击输入框或模板按钮，触发跳转到 /login，携带 redirect=%2F
3. 登录成功后，自动跳转回首页，输入框可用
4. 首页右上角显示登录/注册按钮，已登录显示用户名和下拉菜单

### US-002：项目列表认证守卫
1. 未登录用户访问 /projects，浏览器 URL 变为 /login?redirect=%2Fprojects
2. 登录成功后，自动跳转回 /projects
3. 项目列表显示当前用户的项目（服务端按 userId 隔离）

### US-003：应用归属账号
1. 已登录用户创建应用，API 请求携带会话 cookie
2. 服务端返回的项目数据中，userId 字段正确（服务端已实现）
3. 刷新页面后，项目列表仍显示该应用
4. 新设备登录后，项目列表显示之前创建的应用

### US-004：移除游客模式入口
1. AuthPage 登录页和注册页不显示"游客模式进入"按钮
2. 移除 enterAsGuest 函数及相关 UI

### US-005：登录状态持久化与恢复
1. 登录后关闭浏览器，重新打开应用，自动恢复登录状态（无需重新登录）
2. 会话过期（服务端返回 401）时，显示 toast 提示"会话已过期，请重新登录"，跳转到登录页

### US-006：登出后清理本地项目缓存
1. 点击登出按钮，localStorage 中的 atoms.projects 和 atoms.projects:* 键被清除
2. 登出后跳转到首页，显示登录引导

## 5. 非目标

本次需求不包含以下内容：

1. **游客数据迁移**：游客期间创建的应用不会自动迁移到新注册账号（属于 P2 延后需求）
2. **离线模式**：API 不可用时的离线创建能力（属于 P2 延后需求）
3. **第三方登录**：微信、GitHub 等第三方登录（属于 P1 延后需求）
4. **项目分享**：将项目分享给其他用户（属于 P2 延后需求）
5. **项目协作**：多人协作编辑同一项目（属于 P2 延后需求）

## 7. 中断点分析（当前创建流程）

### 7.1 已发现的中断点

| 编号 | 中断点 | 描述 | 严重程度 | 解决方案 |
|------|--------|------|----------|----------|
| I-001 | 游客可直接创建应用 | 未登录用户可在首页输入需求创建应用，应用存储在 localStorage，不归属账号 | 高 | F-001 登录守卫 |
| I-002 | 项目列表页无认证守卫 | 未登录用户可访问 /projects，看到 localStorage 中的游客项目 | 中 | F-002 项目列表页守卫 |
| I-003 | 游客模式入口存在 | AuthPage 提供"游客模式进入"选项，与"登录后才能创建"冲突 | 高 | F-003 移除游客入口 |
| I-004 | 登出不清理本地缓存 | 登出后 localStorage 仍保留项目数据，换账号登录会看到上一个账号的项目 | 中 | F-004 登出清理缓存 |
| I-005 | 会话过期无提示 | 会话过期后，API 返回 401，前端无统一处理 | 低 | F-005 会话过期处理 |
| I-006 | 登录后不返回原页面 | 登录成功后固定跳转首页，不返回登录前访问的页面 | 低 | F-006 登录后重定向 |

### 7.2 流程图（目标状态）

```
用户访问首页
    │
    ├── 已登录？
    │       ├── 是 → 显示输入框，可创建应用
    │       └── 否 → 显示登录引导，禁用输入框
    │
用户点击创建/模板
    │
    ├── 已登录？
    │       ├── 是 → 创建应用，关联到账号
    │       └── 否 → 跳转登录页
    │
登录成功
    │
    └── 返回原页面（redirect 参数）
```

## 8. 技术约束

- 技术栈：React 18 + Vite + TypeScript + Tailwind + Zustand
- 认证：HttpOnly cookie 会话，前端不存储敏感信息
- 存储：localStorage 优先（游客模式已废弃，登录后优先 API 同步）
- API 同步：服务端已支持 userId 隔离，前端需确保登录态调用
