# Litpp Demo 设计规范 v1

> 作者：dev-litpp-ux-designer
> 版本：v1（Iteration 1）
> 适用范围：Litpp Demo 全部界面（首屏、工作台、对话面板、预览面板、侧栏历史）
> 本规范是前端实现的唯一视觉与交互依据。与本文冲突的实现一律按本文修改。

## 0. 设计基调

### 0.1 Design Read

工具型 AI App Builder 工作台产品（非营销页）。用户在两个心智场景间切换：首屏是"下达指令"（一个输入框就是产品），工作台是"盯住产出"（对话与预览双栏）。视觉语言为深色科技感、边框优先、克制用色。参考 atoms.dev / v0 / bolt.new 的信息形态，但视觉身份必须与它们拉开距离。

### 0.2 基调参数

| 参数 | 取值 | 说明 |
|---|---|---|
| DESIGN_VARIANCE | 4 | 工具 UI 以结构清晰为先；首屏允许居中（输入即产品核心），靠模板 chips 左对齐、品牌左上角、历史入口右上角打破完全对称 |
| MOTION_INTENSITY | 4 | 动效只服务于反馈、状态转换、层级引导，无装饰性循环动画 |
| VISUAL_DENSITY | 6 | 工作台密度：紧凑但不挤压，4px 间距基准 |

### 0.3 与 taste-skill 的关系

taste-skill 面向落地页/作品集，本项目是工具型产品，属于其第 13 节声明范围之外；但以下反 AI 味基线全部适用，并作为所有视觉决策的评审门槛：

1. 拒绝 AI 紫：全站无紫色系、无霓虹渐变光斑、无紫色按钮辉光（LILA 规则）
2. 拒绝无个性默认字体：不使用项目 CLAUDE.md 禁用字体清单中的字体，主字体明确选型（见 1.2）
3. 单一强调色锁定：全站只有 atom 绿一个强调色，任何组件不得引入第二种品牌色
4. 圆角系统锁定：全站只用 4 档圆角（见 1.4），禁止未定义值
5. 单主题锁定：默认深色，支持浅色切换；同屏不出现主题混用
6. 动效必须有动机：每个动画能说出一句话的理由（反馈/状态转换/层级），说不出就不做
7. 拒绝 AI 味文案：不用夸饰动词，不用假精确数字，空态与错误文案写 plainly
8. 完整状态闭环：任何界面不允许只有"成功态"，四态必须齐备（见第 3 节）
9. 拒绝纯黑纯白：深色底用 #09090b，浅色底用 #fafafa，主文字不用 #000/#fff

### 0.4 与 iconify 的关系

全站图标统一来自 iconify 体系，主集 lucide，补集 tabler；禁止手撸 SVG 图标（项目铁律）。具体应用点见第 2 节。

主色选型理由（明确，不接受实现期更换）：

1. 含义贴合：绿是"生成、成长、可用"的颜色。本产品的核心时刻是"应用活了"，预览就绪、生成完成都用同一个绿，情绪与功能一致

### 1.2 字体表

| Token | 字体栈 | 用途 |
|---|---|---|
| font-display | "Space Grotesk", font-sans 回退 | 品牌字标 Litpp、首屏大标题 |
| font-sans | "Space Grotesk", "PingFang SC", "HarmonyOS Sans SC", "MiSans", "Microsoft YaHei", "Noto Sans SC", system-ui, "Segoe UI", sans-serif | 全部 UI 文字 |
| font-mono | "JetBrains Mono", "SF Mono", "Cascadia Code", "Menlo", "Consolas", monospace | 代码、已耗时计时器、文件计数、版本号、字数计数 |

字体选型理由（明确，不接受实现期更换）：

1. 主字体 Space Grotesk：几何骨架带工程感，与"代码生成"的产品气质一致；开源（OFL 协议），可通过 @fontsource-variable/space-grotesk 自托管，无外部 CDN 依赖；是刻意选择，不是禁用字体清单的默认项
2. 代码字体 JetBrains Mono：连字可关、数字等宽、1/l/I 区分度高，通过 @fontsource-variable/jetbrains-mono 自托管；计时刻度用 tabular-nums 不跳动
3. 不选对标产品同款（v0 用的 Geist 一族），避免视觉上"套壳 v0"
4. 中文回退交给系统黑体（PingFang / HarmonyOS / 雅黑 / Noto），首版不自托管中文 webfont（体积大收益低）；若评审发现各平台中文渲染差异影响品质，v2 再引入 Noto Sans SC 子集
5. 中文字重只用 400 / 500 / 600，禁用细字重中文（系统黑体细重在深底上发虚）

### 1.5 动效表

| Token | 值 | 用途 |
|---|---|---|
| duration-instant | 80ms | 按压反馈（active 缩放）、checkbox |
| duration-fast | 140ms | hover、焦点环、tooltip 出入 |
| duration-base | 200ms | 新消息入场、面板开合、toast 出入、阶段切换 |
| duration-slow | 280ms | 首屏与工作台视图切换、全屏切换、对话/代码视图切换 |
| ease-standard | cubic-bezier(0.22, 1, 0.36, 1) | 全部进出场与状态过渡（ease-out 族） |
| ease-linear | linear | 仅循环动画（spinner、shimmer、脉冲、光标闪烁） |

循环动画规格：

| 名称 | 规格 | 动机 |
|---|---|---|
| spinner | 旋转 0.9s linear infinite | 表达"进行中"（阶段节点、按钮内） |
| skeleton-shimmer | 高光扫过 1.6s linear infinite | 骨架屏表达"内容将出现在此" |
| generating-pulse | 不透明度 0.4 到 1 往返 1.2s | 侧栏"生成中"语义状态点（真实语义，非装饰） |
| caret-blink | 流式文本尾部光标 1s step 闪烁 | 表达流式未结束 |
| typing-dots | 三点起伏 1.2s | 表达"等待模型返回"（超过 2 秒无流式分片时出现） |

进出场规格：

| 场景 | 规格 |
|---|---|
| 新消息入场 | opacity 0 到 1，translateY 6px 到 0，duration-base，ease-standard |
| 阶段节点完成 | 节点图标淡入替换，duration-base；整段折叠为摘要行 duration-base |
| 首屏到工作台 | 工作台整体 opacity 0 到 1 + 预览面板 scale 0.98 到 1，duration-slow，ease-standard |
| 预览热更新替换 | 旧画面无动画直接替换（见第 5 节步骤 5，替换必须无闪烁无白屏） |
| 按压反馈 | active 时 scale(0.98)，duration-instant |

规则：

1. 只动 transform 与 opacity，不动 width / height / top / left
2. prefers-reduced-motion: reduce 时：全部循环动画停止（spinner 改为静态圆环加文字"生成中"，shimmer 改为静态浅色块，脉冲点改静态实心点，光标不闪），位移类入场改为仅 opacity
3. 每个动画必须能回答"它传达了什么"（反馈/状态转换/层级引导），回答不了就删（taste-skill MOTION MUST BE MOTIVATED）
4. 禁止窗口 scroll 监听驱动动画；本项目工具 UI 基本用不到滚动动效，消息列表自动滚动用 scrollIntoView 即可

## 2. 图标规范（iconify 体系）

1. 实现：`@iconify/react`，图标数据离线打包（build 时引入集合，不依赖运行时 API 请求）
2. 图标集：主集 lucide（前缀 `lucide:`），tabler（前缀 `tabler:`）仅作 lucide 缺格时的补充；同一界面不混用两集
3. 禁止手撸 SVG 图标（项目铁律）；iconify 找不到合适图形时优先换语义近似的 lucide 图标，而不是画
4. 尺寸刻度：14px（徽章内、caption 行内）、16px（按钮与输入框内、行内动作）、20px（工具栏、面板标题）、24px（空态主图标、阶段节点）
5. 描边：统一 strokeWidth 2（lucide 默认），颜色一律 currentColor，继承文字色；禁止单独给图标上色（语义色场景除外，此时图标与语义文字同色）
6. 交互图标必须有 aria-label 或按钮内文字；纯图标按钮必须带 tooltip（title 属性起步，v2 换自绘 tooltip）

全站动作与图标映射表（前端照此取用，不得自创映射）：

## 4. 生成进度可视化专项规格

体验铁律：用户必须始终知道系统在做什么。本节是"生成中"体验的完整规格，前端照此实现，不得简化为转圈。

### 4.1 阶段指示器

位置：对话面板最新 AI 消息位，AI 消息头内嵌。

结构：水平三节点 stepper，节点依次为：分析（lucide:search-code）、生成（lucide:hammer）、审查（lucide:shield-check）。节点间以 1px border-strong 连线。

节点四态样式：

| 节点态 | 图标 | 名称文字 | 附加 |
|---|---|---|---|
| pending | 24px，text-tertiary | caption，text-tertiary | 无 |
| active | 24px，atom-400，外圈 lucide:loader-circle 旋转（0.9s） | caption，atom-300 | 节点下方 body-sm 描述行，见 4.2 |
| done | 16px lucide:circle-check，atom-500 | caption，text-secondary | 无 |
| stopped | 16px lucide:square，text-secondary | caption"已停止" | 见 4.4 |

三阶段全部 done 后 1.2 秒，整段指示器折叠为一行摘要（title-sm）：`完成 分析、生成、审查，用时 34.2s`（用时为 mono-metric）。摘要行可点击展开回看各阶段。

### 4.2 阶段描述行（active 节点下方）

每阶段固定两条描述文案，10 秒轮换一次（淡入淡出 duration-base）：

| 阶段 | 描述文案 |
|---|---|
| 分析 | 正在拆解需求要点 / 正在确定页面结构与数据 |
| 生成 | 正在编写页面代码 / 正在接入交互逻辑与数据存储 |
| 审查 | 正在检查代码完整性 / 正在修复发现的问题 |

### 4.3 等待反馈阶梯（核心验收项）

| 触发条件 | 反馈 |
|---|---|
| 0 到 2 秒 | 阶段指示器已出现，active 节点 spinner 旋转；无需额外文案 |
| 超过 2 秒无任何流式分片 | active 节点描述行尾部出现 typing-dots（三点起伏）；已耗时计时器持续走（mono-metric，0.1s 精度，格式 12.4s，超过 60s 转 1m04s） |
| 超过 15 秒无流式分片 | 描述行替换为：模型响应较慢，仍在等待。计时器不变 |
| 超过 45 秒无流式分片 | 指示器下方出现 warning 语义提示行 + 停止按钮转为 danger 描边强调：连接不稳定，可以停止后重试，已生成的部分会保留。 [停止] |
| 流式恢复 | 提示行立即消失，回到正常流式呈现，无需用户操作 |

任何时刻用户都能看到：当前阶段名、已耗时、停止按钮。三者缺一即验收失败。

### 4.4 停止（取消）行为

触发：点击停止按钮或按 Esc（焦点在工作台内时）。

表现：流立即终止；阶段指示器当前节点转 stopped 态；已生成的部分内容保留在消息中并折叠为"部分结果"（可展开）；指示器下方出现两个动作：`基于当前结果继续`（ghost 按钮）与 `重新生成`（主按钮）。

文案：已停止。已生成的部分已保留，用时 {耗时}。

### 4.5 流式内容呈现

1. AI 文本消息：流式追加，尾部 caret-blink 光标，自动滚底；用户上滚即暂停自动滚动（详见 3.3）
2. 代码内容：流式期间以折叠代码块呈现（默认收起，显示已生成行数 caption：`已生成 128 行`），生成完成后自动展开；避免流式全幅代码导致对话区抖动
3. 首个可运行版本就绪时：预览面板从构建骨架切换为真实画面（duration-slow，scale 0.98 到 1），同时对话流内追加一条系统消息：`预览已就绪，可以开始对话式修改。`

## 5. 交互流程（全链路文字版）

覆盖：输入需求 → 提交 → 生成 → 预览 → 迭代修改 → 保存。每步给出：用户动作、系统反馈、异常分支（触发条件 → 表现 → 恢复路径）。

### 步骤 1：输入需求（首屏）

用户动作：进入首屏，点击或直接键入输入框；可点击模板 chips；Enter 或点击 lucide:arrow-up 按钮提交；Shift+Enter 换行。

系统反馈：

1. 输入框聚焦即显示 focus-ring（2px #3dd598，offset 2px），边框 border-strong
2. 右下角实时字数（mono-metric，`0/2000`）
3. 输入为空时提交按钮禁用（text-tertiary 图标）；有内容即激活（atom-500 底）
4. 点击模板 chip：文案完整填入输入框并聚焦，光标在末尾；chip 本身不变选中态

异常分支：

| 触发 | 表现与恢复 |
|---|---|
| 空内容提交 | 按钮禁用使其不可达；若通过 Enter 绕过，输入框边框闪一次 border-strong（duration-fast），不弹错误 |
| 超过 2000 字 | 计数变 danger 色；超出部分无法继续输入；caption 提示：最长 2000 字，试着精简一下需求。 |
| 粘贴超长文本 | 自动截断到 2000 字并出现上述提示，不静默丢弃 |

### 步骤 2：提交（首屏 → 工作台）

用户动作：Enter 或点击提交。

系统反馈：

1. 按钮立即进入内联 spinner（最短呈现 120ms，防闪烁）
2. 200ms 内切换到工作台（duration-slow 过渡）；创建项目"未命名项目"，侧栏顶部插入并高亮
3. 用户消息立即回显在对话面板（不做乐观假回显之外的事：AI 侧直接进入分析阶段指示器）
4. 项目名以需求首句生成：取前 12 字截断，用户可后续在顶栏改名

异常分支：

| 触发 | 表现与恢复 |
|---|---|
| 提交请求失败（网络/服务错误） | 留在首屏，错误条出现在输入框上方（见 3.1 错误态），输入内容与光标位置保留，一键重试 |
| 提交成功但 500ms 内未收到工作台初始化确认 | 工作台仍切入，对话面板显示生成中态；若 5 秒无后续事件按步骤 3 的超时阶梯处理 |

### 步骤 3：生成（工作台，阶段可视化）

用户动作：观看；随时可停止（按钮或 Esc）；可在输入框继续输入。

系统反馈：按第 4 节完整执行（阶段指示器、描述行、等待阶梯、已耗时、停止）。预览面板进入构建态（见 3.4 loading）。

异常分支：

| 触发 | 表现与恢复 |
|---|---|
| 模型返回被内容策略拒绝 | 对话面板错误卡片（内容类文案），预览面板保持空态；恢复路径：修改需求重发 |
| 流中断（连接断开） | 错误卡片（网络类），已生成部分保留；恢复路径：重试（从断点续传或整轮重试由前端策略决定，用户无感） |
| 45 秒无流式分片 | 等待阶梯第 4 档（warning 提示 + 停止强调）；用户可选择继续等或停止 |
| 用户停止 | 按 4.4 执行；项目状态标记为"已停止"，可继续或重生成 |

### 步骤 4：预览就绪（首次）

用户动作：在预览面板查看、操作生成的应用；切换设备尺寸；刷新；全屏；切代码视图。

系统反馈：

1. iframe 沙箱加载（sandbox 属性 + srcdoc），握手成功后工具条全部激活
2. 设备切换：三档预设宽度（桌面 100% / 平板 768px / 手机 390px），切换即重载沙箱，画布居中且带 radius-lg 外框；当前设备图标为 accent 色
3. 刷新（lucide:rotate-cw）：重载沙箱，工具条图标旋转一圈（duration-slow）
4. 全屏（lucide:maximize-2）：预览面板铺满视口（z-fullscreen，shadow-3），Esc 或 lucide:minimize-2 退出
5. 代码视图（lucide:code）：右侧面板切换为只读代码（mono-code，语法高亮，bg-inset 底），顶部显示文件名与 `已生成 {n} 行`，附"复制"按钮（点击后图标变 lucide:circle-check 1.2 秒）；lucide:eye 切回预览
6. 新窗口打开（lucide:external-link）：沙箱内容在新标签页打开

异常分支：

| 触发 | 表现与恢复 |
|---|---|
| 沙箱 3 秒未握手 | 按 3.4 错误态处理（沙箱超时文案 + 刷新/回退/重试） |
| 运行时错误（postMessage 错误上报） | 错误面板显示首条错误摘要 + 三动作；"回退上一版本"恢复到最近正常版本并提示：已回退到上一版本，可在左侧继续描述修改方向。 |
| 全屏下出错 | 退出全屏并展示错误面板（错误必须在非全屏层可操作） |

### 步骤 5：迭代修改（对话式增量更新）

用户动作：在对话面板输入修改需求（如"把主色换成蓝色"），Enter 提交。

系统反馈：

1. 用户消息回显；本轮生成流程复用第 4 节（阶段指示器重新走分析到审查，描述行文案不变）
2. 旧预览保留可交互，工具条出现"更新中"指示（见 3.4 生成中）
3. 新版本就绪：画布无闪烁替换（直接 srcdoc 替换 + 握手完成后同帧切换，禁止白屏中间帧）；对话流追加系统消息：`已更新，这是第 {n} 版。`
4. 每个成功版本形成快照；预览面板错误时提供"回退上一版本"；对话中每条生成完成的消息附"查看此版本"链接（点击将预览切至该快照，只读标识：工具条左侧 caption `版本 {n}（只读）`）

异常分支：

| 触发 | 表现与恢复 |
|---|---|
| 本轮生成失败 | 错误卡片（见 3.3），旧预览不受影响继续可用；恢复：重试或修改需求 |
| 新版本构建失败但旧版本正常 | 预览面板显示错误面板，旧版本通过"回退上一版本"恢复；对话面板同步错误卡片 |
| 用户在生成中连续提交 | 进入队列：消息回显后显示 lucide:clock + caption `已加入队列，当前任务完成后自动开始。`；队列逐个执行，每个任务有自己的阶段指示器 |

### 步骤 6：保存与导出

系统行为（用户无感知为主）：

1. 自动保存：每次生成或迭代完成即写入 localStorage（项目元数据、消息历史、最新代码、版本快照最近 5 个）；侧栏条目时间戳实时更新（caption 相对时间，如"3 分钟前"）
2. 静默原则：保存成功不弹提示（不打断心流）；侧栏条目时间戳即保存证据
3. 导出：顶栏 lucide:download，导出单文件 HTML（自包含），文件名 `{项目名}.html`

异常分支：

| 触发 | 表现与恢复 |
|---|---|
| localStorage 写入失败（空间满） | 顶栏下方全局错误条：本地保存失败，存储空间可能已满。 [导出备份] [重试保存]；不清除任何已有数据 |
| 导出失败 | toast（danger，8 秒，可手动关）：导出失败了，请重试。 |
| 用户清空浏览器数据 | 下次进入为无历史状态（侧栏空态），不报错；首屏正常可用 |

## 7. 可用性守门

1. 键盘可达：Tab 顺序为首屏（输入框 → chips → 提交）与工作台（侧栏 → 对话流 → 输入框 → 预览工具条）；所有可点元素可 Tab 聚焦
2. 快捷键：Enter 提交、Shift+Enter 换行、Esc 停止生成、Esc 退出全屏；快捷键不在焦点位于输入框时误触停止（Esc 在输入框聚焦时优先清空/失焦一次，再按才停止）
3. 焦点可见：focus-ring 全站统一（2px #3dd598 offset 2px），不允许 outline: none 无替代
4. 对比度：正文与 UI 文字 4.5:1 起步（1.1 节已逐项标注达标）；禁用态豁免
5. 目标尺寸：可点击目标最小 32x32px（触屏 44x44px），工具条图标按钮实际命中区 32px
6. 屏幕阅读器关键语义：生成中状态用 aria-live="polite" 播报阶段切换与完成；错误用 role="alert"；流式文本容器 aria-busy
7. 动效降级：prefers-reduced-motion 按 1.5 节执行

## 8. 可测验收点

每条都是可独立验证的检查项，标注验证方法。reality-checker 按此逐条验收。

进度可视化（体验铁律核心）：

1. 生成中，对话面板始终可见：当前阶段名、已耗时计时器、停止按钮，三者同屏。验证：生成期间截图检查三元素
2. 阶段指示器按 分析 → 生成 → 审查 顺序点亮，active 节点有旋转 spinner 与描述行。验证：观察一次完整生成
3. 人为断流（mock）超过 2 秒，描述行尾部出现 typing-dots；超过 15 秒出现"模型响应较慢，仍在等待。"；超过 45 秒出现 warning 提示与停止强调。验证：mock 定时器逐档触发
4. 三阶段完成后 1.2 秒内折叠为摘要行且含总耗时。验证：计时观察
5. 生成期间按 Esc 或点停止，流立即终止且已生成内容保留，出现"基于当前结果继续"与"重新生成"。验证：实际操作
6. 无任何场景出现"只有转圈、没有文案、无法取消"的等待。验证：遍历四视图生成路径

四态完备：

7. 首屏、工作台、对话面板、预览面板、侧栏历史的 loading/生成中/错误/空 四态各有实现且文案与第 3 节一致。验证：mock 各态逐格对照矩阵
8. 空态均有引导与第一个行动入口（首屏模板 chips、对话起手式、预览空态指引、侧栏"开始第一个项目"）。验证：清空数据后逐视图检查

视觉规范：

9. 全站字体渲染为主字体栈（Space Grotesk / 系统中文黑体 / JetBrains Mono），DevTools computed font-family 无禁用清单字体。验证：抽查标题、正文、代码、计时器四类元素
10. 全站无紫色系像素、无渐变背景（DevTools 检查 background-image 无 linear/radial-gradient 装饰用途）。验证：全页面截图 + 样式审查
11. 全站图标 DOM 均为 iconify 渲染，无手写 path SVG。验证：grep SVG path + 检查图标元素 class/data 前缀
12. 全站圆角取值仅在 {0, 6, 10, 14, 9999}px 集合内。验证：遍历 getComputedStyle 的 border-radius
13. 全站间距为 4 的倍数。验证：抽查面板、气泡、工具条 padding/gap
14. 正文与 UI 文字对比度 4.5:1 以上（含占位符）。验证：axe 扫描 + 1.1 节逐项抽测

交互与动效：

15. 提交后 200ms 内切入工作台。验证：Performance 面板计时
16. 所有过渡时长在 80ms 到 280ms 区间，动效曲线取 1.5 节两枚 token。验证：审查 transition/animation 定义
17. prefers-reduced-motion: reduce 下无循环动画运行，spinner 降级为静态圆环加文字。验证：系统开启降级后检查
18. 新消息入场、面板开合等动效仅作用于 transform/opacity。验证：样式审查
19. 键盘全流程可用：Tab 到输入框、Enter 提交、Tab 遍历工具条、Esc 停止/退出全屏；焦点环全程可见。验证：拔掉鼠标走完主流程

错误恢复：

20. 每个错误态包含：发生了什么 + 能做什么 + 至少一个恢复按钮。验证：mock 网络断开、内容拒绝、沙箱超时、存储失败四场景
21. 断网提交：输入内容与光标位置保留，重试一键可达。验证：断网实际操作
22. 沙箱运行错误：提供刷新/回退/重试三动作，回退后旧版本恢复可交互。验证：注入会出错的迭代需求

流式与预览：
