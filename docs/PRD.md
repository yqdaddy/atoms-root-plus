## 1. 背景与目标

为 ROOT AI Native 全栈工程师笔试构建一个对标 atoms.dev 的 AI App Builder Demo：用户用一段自然语言描述需求，由角色化的多 Agent 团队流式生成一个自包含的单文件 HTML 应用，并在隔离沙箱中实时预览、通过对话持续迭代。目标用户是笔试评委与产品演示者，其中相当一部分评委不持有 LLM API Key，因此产品必须在无 Key 条件下依然完整可用。成功标准：任何评委在打开页面后 3 分钟内，无需注册、无需自备 Key，即可完整走通"描述需求、观看 Agent 协作、预览真实可交互的应用、对话修改、刷新后成果不丢"的核心闭环，且至少体验到一个延展能力（模板库快速启动为推荐首选）。

### 1.1 竞品参照（atoms.dev，一手调研结论）

已通过官网与第三方评测确认 atoms.dev 的关键形态：8 个角色化 Agent（Mike 队长、Iris 研究员、Emma 产品经理、Bob 架构师、Alex 工程师、Sarah SEO、Adrian 广告、David 数据分析）、对话式构建、Visual Editor、Race Mode 多模型对比、Atoms Cloud 后端、积分计费。本 Demo 采纳其"多 Agent 角色团队 + 对话驱动 + 即时预览"的核心体验；明确砍掉的部分见第 5 章非目标。

## 2. 用户故事

优先级沿用第 3 章定义：P0 缺失则 Demo 不成立；P1 显著提升体验；P2 锦上添花。

### P0（核心闭环底线）

- **US-001**（P0）作为首次访客，我想要在不注册、不登录的情况下直接进入工作台并获得游客身份，以便零门槛开始体验。
- **US-002**（P0）作为用户，我想要用一个输入框以自然语言描述我想做的应用并提交，以便发起 Agent 团队生成。
- **US-003**（P0）作为用户，我想要在生成过程中看到多个角色化 Agent（如产品经理、架构师、工程师）分阶段接力工作的过程，以便感知这是"一支团队在协作"而不是一个聊天机器人。
- **US-004**（P0）作为用户，我想要看到 Agent 的计划与代码以流式方式逐字呈现，以便在生成过程中有实时反馈、不必对着空白干等。
- **US-005**（P0）作为用户，我想要在生成完成后立刻在右侧预览区看到一个真实可交互的应用，以便确认生成结果是"能用的应用"而非静态图片。
- **US-006**（P0）作为用户，我想要在同一个对话里继续用自然语言提出修改要求（如换颜色、加模块），以便在已有成果上持续迭代而不必推倒重来。
- **US-007**（P0）作为用户，我想要对话记录与最新可用版本被自动保存，刷新或关闭浏览器后重新打开仍能恢复现场，以便工作成果不因一次刷新而丢失。
- **US-008**（P0）作为没有 API Key 的评委或演示者，我想要一键进入演示降级模式并完整走通"描述、Agent 过程、生成、预览、修改、刷新恢复"，以便在零成本、无外部 Key 的情况下完整评估产品。
- **US-009**（P0）作为关心平台安全的用户，我想要生成的应用代码只在隔离沙箱中运行、与主应用物理隔离，以便生成的错误或恶意代码无法破坏平台本身与我浏览器中的数据。
- **US-010**（P0）作为持有 API Key 的用户，我想要在设置中配置自己的模型服务商、模型与密钥，以便用真实 LLM 驱动生成并保持对成本的控制。
- **US-011**（P0）作为用户，我想要在生成失败、流式中断或 Key 无效时得到明确的错误提示并能一键重试，以便单次失败不会卡死整个演示流程。

### P1（显著提升体验，延展能力池）

- **US-012**（P1）作为用户，我想要一个多项目工作台来新建、切换、重命名和删除多个应用项目，以便同时推进多个想法并管理成果。
- **US-013**（P1）作为用户，我想要从模板库选择一个预设场景（如番茄钟、待办清单、数据看板）一键快速启动，以便跳过冷启动、立刻看到完整效果。
- **US-014**（P1）作为用户，我想要生成带数据图表（柱状、折线、饼图）的管理看板类应用，以便看到超出静态落地页的复杂数据场景能力。
- **US-015**（P1）作为用户，我想要在预览区切换桌面与移动视口并手动刷新预览，以便检查应用在不同设备尺寸下的表现。
- **US-016**（P1）作为用户，我想要查看并复制 Agent 生成的源代码，以便信任生成过程、按需取走代码。
- **US-017**（P1）作为用户，我想要回看历史版本并一键回滚到之前某个可用版本，以便一次不满意的修改可以撤销。

### P2（锦上添花，可延后或砍掉）

- **US-018**（P2）作为用户，我想要把项目导出为文件、再导入恢复，以便备份成果或在换设备时带走作品。
- **US-019**（P2）作为进阶用户，我想要同一需求同时跑多个模型并对比结果后择优保留，以便获得更接近 atoms.dev Race Mode 的体验。

## 3. 功能清单

负责角色可选：frontend-developer（前端）、backend-architect（后端/沙箱/持久化）、ai-engineer（AI 流水线）、data-engineer（图表/导入导出）、ux-designer（交互视觉）。任何功能的完成宣称仍须经 reality-checker 独立验证。

| 编号 | 功能 | 说明（what） | 优先级 | 对应 US | 建议负责角色 |
|---|---|---|---|---|---|
| F-001 | 游客模式初始化与首次引导 | 清空状态首次打开即进入工作台，无注册环节；展示首次引导与游客身份标识 | P0 | US-001 | frontend-developer |
| F-002 | Prompt 输入区 | 多行输入、示例提示词（帮助冷启动）、提交按钮与生成中的禁用态 | P0 | US-002 | frontend-developer |
| F-003 | 多 Agent 流水线过程展示 | 至少 3 个角色化阶段（规划、编码、审查类），阶段切换与当前角色状态在对话区可见，呼应 atoms.dev 的角色团队体验 | P0 | US-003 | ai-engineer |
| F-004 | LLM 流式输出与停止 | 对话内容流式逐字渲染；生成中可手动停止；停止后保留已完成部分并可继续对话 | P0 | US-004 | ai-engineer + frontend-developer |
| F-005 | 单文件 HTML 应用生成 | 产出为自包含单文件 HTML（内联样式与脚本），可直接在沙箱中渲染；对产出做基本的可渲染性校验 | P0 | US-002、US-005 | ai-engineer |
| F-006 | 沙箱预览与受控通信 | 生成应用在隔离沙箱（iframe sandbox + srcdoc）中渲染，与主应用隔离；沙箱与主应用间仅经 postMessage 通信且做来源校验（安全铁律） | P0 | US-005、US-009 | backend-architect |
| F-007 | 对话迭代修改 | 多轮对话携带上下文，修改指令作用于当前版本而非全新生成；修改后预览随之更新 | P0 | US-006 | ai-engineer |
| F-008 | 会话与版本持久化 | 对话记录、项目、版本自动写入 localStorage；刷新后恢复最近现场；存储异常有兜底提示 | P0 | US-007 | backend-architect |
| F-009 | 演示降级模式 | 未配置 Key 时的完整替代流程：内置剧本模拟 Agent 过程并产出真实可交互的应用，支持至少 2 轮有可见效果的演示内修改；界面明确标识"演示模式" | P0 | US-008 | ai-engineer |
| F-010 | BYOK 设置 | 配置服务商、模型、API Key；含连接测试；Key 仅存于本地浏览器，不上传 | P0 | US-010 | backend-architect + frontend-developer |
| F-011 | 异常处理与重试 | 生成失败、流式中断、Key 无效、配额超限等场景有明确文案与重试入口；失败不污染已有版本 | P0 | US-011 | frontend-developer + ai-engineer |
| F-012 | 多项目工作台 | 项目列表、新建、切换、重命名、删除；每个项目独立对话与版本；删除有确认 | P1 | US-012 | frontend-developer |
| F-013 | 模板库快速启动 | 内置 3 至 6 个模板场景，一键从模板创建项目并立即获得可预览应用与后续修改能力；**延展能力交付底线，推荐首选** | P1 | US-013 | frontend-developer + ai-engineer |
| F-014 | 数据图表场景 | 生成的应用支持图表类需求（柱状、折线、饼图）；配套图表模板资产保证演示模式下也能出图表应用 | P1 | US-014 | data-engineer |
| F-015 | 预览增强 | 预览区桌面/移动视口切换、手动刷新预览 | P1 | US-015 | frontend-developer |
| F-016 | 生成代码查看面板 | 只读展示当前版本源码，支持一键复制 | P1 | US-016 | frontend-developer |
| F-017 | 版本历史与回滚 | 版本时间线可回看，一键回滚到任一历史可用版本，回滚后对话可继续 | P1 | US-017 | backend-architect + frontend-developer |
| F-018 | 项目导出/导入 | 导出单文件 HTML（直接可打开）与项目完整包（JSON）；支持导入恢复 | P2 | US-018 | data-engineer |
| F-019 | 多模型对比（Race 风格） | 同一需求并行请求多个模型，结果对比后择优保留 | P2 | US-019 | ai-engineer |

**优先级统计**：P0 共 11 项（F-001 至 F-011），P1 共 6 项，P2 共 2 项。

**交付底线声明**：P0 全部 11 项为必交；延展能力按笔试要求至少交付 P1 中 1 项，推荐 F-013 模板库（评委首次体验的起手式），次选 F-014 图表场景；P2 不承诺交付。

## 4. 验收标准

### P0 用户故事（逐条可核对，全部为可观察行为）

**US-001 验收标准**
1. 清空站点 localStorage 后首次打开页面，不出现任何注册或登录门槛，直接进入工作台界面。
2. 界面可见位置（如右上角）显示游客身份标识。
3. 首次进入时存在引导元素（示例提示词或引导文案），用户不看文档也知道下一步该做什么。

**US-002 验收标准**
1. 输入"做一个番茄钟计时器"并提交后，输入框出现该条消息的记录，且 5 秒内对话区出现首个流式响应字符（演示模式下立即出现剧本内容）。
2. 提交后生成过程中输入与提交按钮进入禁用态，防止重复提交。
3. 输入为空时提交按钮不可用。

**US-003 验收标准**
1. 一次完整生成过程中，对话区至少呈现 3 个具名角色化 Agent 阶段（如"产品经理规划中""工程师编码中""审查中"）。
2. 阶段切换在界面上可见（状态标签或消息卡片变化），用户能说出当前处于哪个阶段。
3. 生成结束后各阶段均留有记录，刷新后回看仍完整。

**US-004 验收标准**
1. 流式输出期间文本逐步增长，肉眼可见打字过程，而非结束后一次性出现。
2. 生成中点击"停止"后 1 秒内停止输出，已完成内容保留，且可以继续发起下一轮对话。
3. 全程无页面卡死或整块白屏。

**US-005 验收标准**
1. 生成完成后 5 秒内右侧预览区渲染出应用界面。
2. 预览内应用可真实交互：以番茄钟为例，点击开始后计时数字持续走动；以清单类应用为例，可添加和勾选条目。
3. 预览中的交互不依赖主应用页面刷新即持续生效。

**US-006 验收标准**
1. 在已完成生成的会话中发送"把主色调改成蓝色"，完成后预览中主色变为蓝色。
2. 修改后原有功能不丢失：修改前的交互（如计时、勾选）在修改后仍可用。
3. 连续进行至少 2 轮不同修改，每轮修改均作用于最新版本（第 2 轮保留第 1 轮的效果）。

**US-007 验收标准**
1. 完成一次生成后按 F5 刷新，页面恢复到同一会话：对话记录完整、预览自动恢复最后一个可用版本且可继续交互。
2. 关闭标签页后重新打开 URL，结果同上。
3. 刷新后可直接继续发起修改对话，无需重新生成。

**US-008 验收标准**
1. 全新环境下未配置任何 API Key，页面上存在明确入口进入演示模式。
2. 演示模式下完整走通"输入需求、看到 Agent 过程、生成完成、预览可交互、发起修改、刷新恢复"，中途无任何要求配置 Key 的阻断。
3. 演示模式下发起至少 2 轮修改指令（如换主题色、增删条目），预览均有对应可见变化。
4. 演示模式全程不产生任何外部 LLM API 请求，界面有"演示模式"标识避免评委误以为接了真实模型。
5. 断网状态下演示模式全流程仍可走通。

**US-009 验收标准**
1. DevTools 检查预览容器：生成的应用运行于带 sandbox 属性的 iframe（srcdoc 渲染），不注入主文档、不使用 eval 写入主页面。
2. 在预览中执行 `window.parent.document` 访问被浏览器同源策略拦截（控制台报跨域错误），生成代码无法读取或篡改主应用 DOM 与 localStorage。
3. 沙箱与主应用的通信仅经 postMessage，且接收方校验消息来源；伪造来源的消息被忽略。

**US-010 验收标准**
1. 设置面板可选择服务商与模型、输入 API Key，保存后发起生成走真实 LLM 流式流程。
2. 提供连接测试入口：填入有效 Key 显示测试通过，填入无效 Key 给出明确失败提示。
3. 配置仅写入本地浏览器存储，网络面板中除 LLM 服务商接口外无任何携带 Key 的第三方请求。

**US-011 验收标准**
1. 配置一个故意错误的 Key 后发起生成：出现可理解的错误提示（非英文堆栈、非静默失败），并提供重试与修改配置入口。
2. 流式中途断开时，界面提示中断并保留已完成内容，可一键重试。
3. 任何失败场景下，之前已生成的可用版本不被破坏，刷新后仍可恢复。

### P1 用户故事（每条至少 1 条可核对）

**US-012 验收标准**：可新建第 2 个项目；两个项目对话与版本相互独立；切换后内容正确；删除有确认且删除后不再出现在列表。
**US-013 验收标准**：从模板点击到预览出现完整可交互应用不超过 3 秒且不依赖任何网络请求；基于模板继续发起修改对话可生效。
**US-014 验收标准**：生成（或演示模式产出）的看板类应用包含至少一种图表且随数据变化更新；演示模式剧本中含至少 1 个图表应用。
**US-015 验收标准**：视口切换后预览宽度实际变化（移动视口下布局与桌面不同或出现移动适配）；刷新预览后应用回到初始状态且功能正常。
**US-016 验收标准**：代码面板展示的内容与当前预览版本一致；一键复制后粘贴到任意编辑器内容完整。
**US-017 验收标准**：存在至少 2 个历史版本时可回滚到较早版本，回滚后预览与代码面板均显示该版本内容，且可继续对话迭代。

### P2 用户故事（每条至少 1 条可核对）

**US-018 验收标准**：导出的 HTML 文件双击可直接在浏览器打开使用；导出的项目包经导入后对话与版本恢复完整。
**US-019 验收标准**：配置至少 2 个模型后，同一需求可发起对比生成，两个结果均可预览，择优保留后后续对话基于所选结果继续。

## 5. 非目标

以下内容明确不做，防止范围蔓延。reality-checker 不应将下列项计为缺失：

1. **真实注册/登录与账号体系**：以游客模式（localStorage）满足笔试的"初始化"要求，不做邮箱注册、OAuth、密码找回。
2. **服务端与云后端**：不部署任何自建后端；不承诺 atoms.dev 的 Atoms Cloud 类能力（用户系统、数据库、托管）。Supabase 云同步仅作架构预留，不在本次交付承诺内。
3. **生成应用的后端能力**：生成物限定为纯前端单文件 HTML 应用，不含真实数据库、支付、鉴权等服务端功能。
4. **SEO/广告投放类 Agent**：对标 atoms.dev 的 Sarah（SEO）与 Adrian（Ads）不进 Demo，Agent 流水线聚焦规划、编码、审查。
5. **可视化拖拽编辑器**：atoms.dev 的 Visual Editor 不做，迭代一律走对话。
6. **社区与分发**：不做 Discover 案例广场、作品分享链接、多人协作、评论。
7. **移动端原生 App/小程序**：仅保证响应式网页在桌面浏览器可用。
8. **商业化**：不做积分、计费、订阅（atoms.dev 的 credit system 不进 Demo）。
9. **生成质量军备竞赛**：不追求生成复杂多页应用；以单文件、单页、可交互为质量线，复杂场景靠模板兜底。
