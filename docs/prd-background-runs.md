# PRD：生成任务与页面生命周期解耦

## 1. 背景与目标

当前生成与 SSE 连接强绑定（server/routes/llm.ts:146 将请求 signal 直通生成链路），关闭或刷新页面即终止生成，用户被迫守在页面前等待。目标：生成在服务端独立于页面连接存活，用户可随时离开、随时回来接续。成功标准：下方 6 条用户故事的验收标准全部通过。

## 2. 用户故事

- US-001 作为普通用户，我想要在生成进行中关闭标签页或刷新浏览器后服务端生成继续执行至完成，以便页面操作不丢失生成结果。
- US-002 作为普通用户，我想要重新进入生成中的项目时看到"生成进行中"状态与当前阶段（如工程师生成中、审查中），以便掌握进展并继续实时观看后续输出。
- US-003 作为普通用户，我想要在离开期间生成完成后回来直接看到就绪结果（文件已更新、消息完整）并有"生成已完成"提示，以便无需任何操作即可使用成果。
- US-004 作为普通用户，我想要主动点击停止时生成真正终止，以便取消是唯一可控的终止途径，其余情况生成不受干扰。
- US-005 作为普通用户，我想要在 A 项目生成中切换到 B 项目再切回时 A 的进度不丢失，以便多项目并行不被打断。
- US-006 作为普通用户，我想要在离开期间生成失败后回来看到错误信息与重试入口，以便知晓失败原因并一键重试。

## 3. 功能清单

- F-001 P0 生成任务与连接解耦：断连、刷新不终止服务端生成（建议负责：backend-architect）
- F-002 P0 活跃任务查询：进入项目可获取任务状态（进行中、已完成、失败）与当前阶段（建议负责：backend-architect）
- F-003 P0 前端恢复接入：进入项目时识别活跃任务并接续实时输出（建议负责：frontend-developer）
- F-004 P0 结果感知：回来后展示"生成已完成"提示，或失败信息加重试入口（建议负责：frontend-developer）
- F-005 P0 显式取消保持唯一终止途径：复用现有 POST /api/llm/cancel，断连不得触发取消（建议负责：backend-architect）
- F-006 P1 版本落库保持：后台完成的生成按现有 saveVersion 语义正常产生版本记录（建议负责：backend-architect）
- F-007 P1 阶段流转可见：恢复接入后阶段变化（生成中到审查中等）实时呈现（建议负责：ai-engineer）

## 4. 验收标准

- AC-001（US-001）：发起一次预期耗时超过 30 秒的生成，确认输出已开始后关闭标签页；静置等待超过原生成时长后重新打开该项目，文件与消息为完整最终结果。全程无页面操作而结果完成，即证明服务端未因断连终止。
- AC-002（US-001）：以浏览器刷新（F5）替代关闭标签页，重复 AC-001 流程，结果一致。
- AC-003（US-002）：断连期间重新打开该项目，3 秒内显示"生成进行中"与当前阶段文案；停留观察，后续流式输出持续出现，阶段文案随推进更新（如从生成中变为审查中）。
- AC-004（US-003）：离开至生成完成后回来，文件内容与消息为最终完整版，页面出现可感知的"生成已完成"提示；打开版本历史，本次结果按现有 saveVersion 语义新增一条版本记录。
- AC-005（US-004）：生成中点击停止，输出在 5 秒内不再增加，任务状态变为已终止；对比关闭页面操作，后者不产生相同效果。
- AC-006（US-005）：A 项目生成中切换到 B 项目正常操作，再切回 A，A 的阶段与输出连续无缺失，生成未中断也未重启。
- AC-007（US-006）：令一次生成必然失败（如临时注入非法配置），离开后回来看到具体错误信息与"重试"按钮；点击重试可重新发起生成并正常推进。

## 5. 非目标

- 不做跨服务器分布式任务队列，单实例内管理活跃任务即可。
- 不做生成历史列表页，仅支持活跃任务（进行中或刚结束未查看）的恢复。
- 不做移动端推送通知。
- 批准流程（approval_required）期间的断连保持现有会话语义，不纳入本次改造。

## 6. 开放问题

- 服务进程重启时活跃任务如何呈现（标记失败还是视为丢失）？请 backend-architect 给出边界方案。（负责人：backend-architect）
- 恢复接入后是重放离开期间的完整增量输出，还是仅从接入点继续？影响 US-002 与 US-003 的体验口径。（负责人：ai-engineer）
- 活跃任务结果（含未查看的完成与失败状态）保留多久后清理？（负责人：product-manager）
