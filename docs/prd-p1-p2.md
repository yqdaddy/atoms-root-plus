# PRD：P1 作品广场（Gallery）与 P2 项目知识库（Project Resources）

版本：v1.0（2026-09-29）　负责角色：dev-litpp-product-manager　下游：frontend-developer / backend-architect / ai-engineer / reality-checker

说明：P0 分享链接功能已上线，本 PRD 不覆盖其既有验收，仅在广场只读预览处复用其快照能力。

竞品参考（一手核实）：atoms.dev 设有 /discover 作品发现页，支持 Latest 视图切换；其站内未见明确的复刻机制。本产品广场对齐其浏览形态，并以"一键复刻"形成差异化闭环。

---

## 功能 1：作品广场 Gallery（P1）

### 背景
平台已有私有项目与分享链接，但缺少公开的作品发现入口；广场让用户公开展示作品、让访客发现并一键复刻，形成"浏览、预览、复刻、迭代"的增长闭环。

### 用户故事
- US-G1：作为已登录用户，我希望把项目发布到广场并可随时取消发布，以便自主控制作品的公开状态。
- US-G2：作为访客（含未登录用户），我希望公开浏览 /gallery 广场列表，以便发现他人的作品。
- US-G3：作为广场访客，我希望点击卡片进入只读预览，以便查看作品实际效果且不干扰作者。
- US-G4：作为已登录用户，我希望一键复刻（fork）广场项目为我账号下的新项目并进入工作台，以便在他人成果基础上继续迭代。
- US-G5：作为广场访客，我希望按"最新"或"最多复刻"排序浏览广场，以便快速定位感兴趣的作品。

### 验收标准
- AC-G1.1 发布成功后，项目卡片出现在 /gallery 列表，卡片包含项目名、作者名、发布时间、简介，以及预览缩略图或标签（两者至少其一）。
- AC-G1.2 取消发布后，该卡片不再出现在 /gallery 列表；重新发布后卡片恢复，发布时间更新为最近一次发布时间。
- AC-G2.1 使用无会话 cookie 的浏览器（隐身模式）直接访问 /gallery，页面正常加载列表，无需登录，HTTP 状态 200。
- AC-G3.1 点击卡片进入只读预览（复用 /share/:id 或快照页），预览页不提供任何编辑入口。
- AC-G3.2 只读预览基于项目快照：作者在预览期间继续编辑项目，已打开的预览内容不变，且预览行为不影响作者项目数据。
- AC-G4.1 已登录用户点击复刻后，产生一个新项目：归属当前登录用户、内容为广场项目当前快照，并进入工作台可继续编辑。
- AC-G4.2 复刻不修改原项目的任何数据；原项目的复刻计数加一，并在"最多复刻"排序中正确体现。
- AC-G4.3 未登录用户点击复刻时，跳转登录页，不产生任何项目数据。
- AC-G5.1 /gallery 支持两种排序："最新"（按发布时间倒序，为默认排序）与"最多复刻"（按复刻数倒序），切换后列表顺序与数据一致。

### 非目标
- 不做点赞、评论、收藏、浏览量统计等社交互动
- 不做内容审核、举报、下架工作流
- 不做分类目录与标签筛选体系（标签仅作卡片展示元素）
- 不做复刻来源链（fork 树）与作品榜单

## 功能 2：项目知识库 Project Resources（P2）

### 背景
生成结果常需遵循用户自有的规范与数据结构；提供项目级文本资料管理，并在生成时将资料注入上下文，以提升生成命中率。

### 用户故事
- US-R1：作为已登录用户，我希望通过粘贴文本或上传 .md/.txt/.json 文件为项目添加资料，以便沉淀生成所需的规范与数据结构。
- US-R2：作为已登录用户，我希望在资料面板查看资料列表、查看完整内容并删除资料，以便维护项目知识库。
- US-R3：作为已登录用户，我希望发起新生成时资料内容自动作为上下文注入工程师 prompt（由后端拼接），以便生成结果遵循资料中的规范与数据结构。
- US-R4：作为已登录用户，我希望资料随项目持久化在服务端，以便刷新页面或更换设备后资料仍可用。

### 验收标准
- AC-R1.1 粘贴文本提交后，资料出现在面板列表，条目包含名称、大小、添加时间。
- AC-R1.2 上传 .md/.txt/.json 文件可成功入库；上传其他扩展名（如 .png、.pdf）被拒绝，并提示支持的文件类型。
- AC-R1.3 单条内容超过 16KB 时拒绝保存并提示单条上限；项目资料总量达到 32KB 时拒绝新增并提示总量上限。
- AC-R2.1 点击资料条目可查看完整原始内容；删除后列表即时移除，且该资料不再出现在后续生成的注入内容中。
- AC-R3.1 项目存在资料时发起新生成，工程师 prompt 中包含资料全文拼接内容（可经后端请求日志核对）；项目无资料时不注入，生成流程行为与现状一致。
- AC-R3.2 单次生成注入的资料内容总量不超过 32KB，注入不改变生成请求的其余环节。
- AC-R4.1 资料存储于服务端 SQLite 并关联项目；清除浏览器缓存或更换浏览器后登录同一账号，资料列表与内容完整可查看。
- AC-R4.2 游客（未登录）项目不展示资料功能入口；资料相关接口对无会话请求返回未授权，不落库。

### 非目标
- 不做资料全文检索、向量化、RAG 与按需召回（注入方式为全文拼接）
- 不做图片、PDF 等二进制资料及 OCR
- 不做资料版本历史与多人协同编辑
- 不做资料自动摘要或压缩

## 全局约束与开放问题

全局约束：两功能均面向登录用户与服务端 SQLite 数据（users/sessions/projects/shares 之外新增必要表）；游客模式项目不涉及发布与资料。

开放问题：
1. 取消发布是否使已有 /share/:id 链接失效（当前倾向：不影响，仅从广场下架）？负责人：用户
2. 复刻计数口径：每次点击均计数，还是同一用户对同一项目只计一次？负责人：backend-architect
3. 生成时是否向用户展示"已引用 N 条资料"的提示？负责人：ai-engineer
