  multiFileOutput 保持 undefined（:1434 注释自证）

  → 按校验器语义退化为全量扫描（projectValidator.test.ts 用例 6 后半已证 undefined=全量）

  覆盖存量文件
后果：对含非白名单绝对外域引用的存量项目执行 modify → 存量文件命中 E_CDN_DOMAIN →
白耗 3 次重试（且 hint"请修正后重新输出完整文件"与 diff 格式要求相悖）→ 用户收到
"自动重试后仍有 N 处结构问题"警告（llm.ts:1503-1509）。交付本身仍成功（validationIssues
降级通道），但直接违背 :1456 注释"存量项目的历史外部引用不误报"的修复目标。
触发面：存量项目（含 jsdelivr/tailwindcss 之外绝对引用，如修复前生成的 unpkg 项目）+ modify。
建议修复：diff 模式传 changeList 涉及文件路径、容错路径传 changes 涉及文件路径
（即"本次 LLM 实际产出/触碰"的路径），并补 2 条单测（diff 迭代不扫存量、容错迭代只扫
变更文件）。
